Next Rust is a full-stack web framework for Rust that works the way Next.js does. Folders in app/ become routes, layouts nest, pages render on the server and stream to the browser, and the whole app ships as one native binary.

If you've built with the Next.js App Router, most of this will feel familiar. The difference is that your pages, data loading, API routes and server actions are plain Rust functions, checked by the compiler before anything runs.

What you get

Filesystem routingpage.rs, layout.rs, loading.rs, error.rs, route groups, dynamic and catch-all segments, parallel and intercepting routes.
Rendering on your termsServer rendering with streaming, static generation, and incremental regeneration. The mode is inferred from your code.
Server actionsForms that post to typed Rust functions, with validation errors, CSRF protection and progressive enhancement.
Very little JavaScriptPages ship no JavaScript unless they use links or islands. The client runtime is about 3 KB gzipped.
One file to deploynext-rust build writes a single stripped binary that carries your pages, config and static files.
Errors at build timeWrong exports, duplicate routes and bad extractor types fail the build with a clear diagnostic.

A first look

A page is a function that returns a view. Put it in a folder and it has a URL:

// app/about/page.rs  →  /about
use next_rust::prelude::*;

pub fn metadata() -> Metadata {
    Metadata::new().title("About")
}

pub fn Page() -> impl View {
    main![
        h1!["About us"],
        p!["We build fast things."],
        a![href("/"), "Back home"],
    ]
}

Data loading is an async function next to the page, and its result is passed in already typed:

pub async fn load() -> Result<Vec<Post>> {
    db::posts().await
}

pub fn Page(Data(posts): Data<Vec<Post>>) -> impl View {
    ul![each(posts, |post| li![post.title])]
}
